# WOBI — פיצ'רים עתידיים (לבדיקה / למימוש)

מסמך עבודה לרעיונות שעוד לא מומשו. כל פיצ'ר: **מה**, **למה**, **UX מוצע**, **נתונים קיימים**, **סקיצת מימוש**, **פתוחות/סיכונים**, **סטטוס**.

סטטוסים: `רעיון` · `מאושר` · `בעבודה` · `בוצע` · `נדחה`.

---

## 1. Drill-down מלא לשחקן — פירוק לפי מחזור

**סטטוס:** רעיון

### מה
לחיצה על שחקן (למשל ב־`/squad`) מציגה כרגע פאנל צף מינימלי בלבד — סיכום עונה + המחזור האחרון:

```
עונה        7
מחזור אחרון  5
דקות        90 · +2
הרכב פותח    1 · 0
בישולים      1 · +3
ספיגות       1 · 0
```

הפאנל הזה מראה רק את **המחזור האחרון**. אנחנו רוצים drill-down עשיר יותר שמראה **מה השחקן עשה בכל מחזור ומחזור** לאורך העונה — נקודות, דקות, ופירוק סטטיסטי לכל סבב.

### למה
- לזהות מגמה/מומנטום (עולה או דועך) לפני החלטת חילוף — לא רק "המחזור האחרון".
- להבחין בין שחקן עקבי לשחקן עם ספייק חד־פעמי שמנפח את ממוצע העונה.
- לראות דקות משחק לאורך זמן (רוטציה, חזרה מפציעה) — קריטי בליגת פנטזיה.

### UX מוצע
שכבתיים, כדי לא לאבד את המהירות של הפאנל הצף:

1. **שכבה 1 — הפאנל הצף נשאר כמו שהוא** (hover/לחיצה קצרה): סיכום עונה + מחזור אחרון. מהיר, לא פולשני.
2. **שכבה 2 — מודאל drill-down** נפתח בלחיצה על "פירוט מלא" בתוך הפאנל (או לחיצה על שם השחקן):
   - כותרת: שם, קבוצה (לוגו), עמדה, מחיר, נק' עונה, `vlfm`, עשירון.
   - **טבלת מחזורים** — שורה למחזור: `מחזור · יריב · דקות · נקודות · פירוק (שערים/בישולים/ספיגות/כרטיסים…)`.
   - **גרף מגמת נקודות** קטן (sparkline/עמודות) לאורך המחזורים.
   - שורת סיכום: ממוצע נק'/מחזור, ממוצע דקות, מס' מחזורים עם 0 דקות.
   - סגירה ב־`Esc` / קליק ברקע. תמיכה מלאה ב־RTL.

**עקרון:** הפאנל הצף = מבט מהיר; המודאל = צלילה. לא מחליפים, מוסיפים.

### נתונים — כבר קיימים ב־DB
אין צורך בייבוא חדש; הנתונים ההיסטוריים כבר נאספים בכל ייבוא מחזור:

| טבלה | תפקיד לפיצ'ר |
|---|---|
| `player_round_stats` | היסטוריית נקודות לכל `(playerId, sport5RoundId)` + `gameweekNumber` + `statsData` (jsonb, אותו פורמט של `statsData` שהפאנל כבר יודע לפרסר). זהו המקור העיקרי לטבלת המחזורים. |
| `player_snapshots` | שורת שחקן מלאה לכל מחזור (`lastRoundPlayerStats` / `lastSeasonPlayerStats`) — גיבוי/הצלבה אם נדרש פירוק שלא נמצא ב־`player_round_stats`. |
| `fixtures` + `gameweeks` | לשלוף את היריב + תוצאה לכל מחזור לצד שורת הסטטיסטיקה. |

הפירוק לכל מחזור עובר דרך אותו `parseStatsDataRaw` / `STAT_LABELS` שכבר קיימים ב־`src/lib/stats.ts` — אפשר לעשות reuse ולא לכתוב פרסר חדש.

### סקיצת מימוש
**החלטות שננעלו:** טעינה **עצלה** (רק בפתיחת המודאל) · גרף מגמה **נכלל כבר ב־v1**.

- **Server:** route ייעודי `/(api)/player/[id]/history` — שאילתה ל־`player_round_stats` לפי `playerId`, ממוינת לפי `gameweekNumber`, join ל־`fixtures`/`gameweeks` ליריב. **לא** לטעון היסטוריה לכל השחקנים ב־`+page.server.ts` (שומר על load מהיר של `/squad`).
- **טעינה עצלה:** fetch לפי `playerId` רק כשהמודאל נפתח.
- **UI:** קומפוננטה חדשה `PlayerHistoryModal.svelte`. הפאנל הצף (`PlayerStatsPanel.svelte`) מקבל כפתור "פירוט מלא" שמעביר `openHistoryId`.
- **גרף (v1):** לפי skill `dataviz` — sparkline/עמודות פשוט של נק' לאורך המחזורים, נגיש בגוונים בהירים/כהים.

### פתוחות / סיכונים
- מיפוי `sport5RoundId` → `gameweekNumber` הוא nullable ב־`player_round_stats`. לוודא שכל השורות ממופות, אחרת מחזורים "יעופו" מהטבלה. (אולי fallback להצגה לפי `sport5RoundId` כשאין מיפוי.)
- שחקנים שעברו קבוצה באמצע העונה — עמודת "יריב" צריכה להתבסס על ה־snapshot של אותו מחזור, לא על הקבוצה הנוכחית.
- כמות מחזורים גדלה לאורך העונה — לוודא שהמודאל נשאר קריא (גלילה פנימית, לא כל המסך).

## 2. Drill-down למשחק — מה ידוע על ההתמודדות

**סטטוס:** רעיון

### מה
לחיצה על משחק (בכל מקום שהוא מוצג — רשימת "משחקי מחזור" ב־`/squad`, וגם `FixtureStrip` המיני על כרטיס שחקן) פותחת מודאל שמרכז **כל מה שאנחנו יודעים על המשחק**:
- תוצאה, תאריך/שעה, שתי הקבוצות (לוגו) + דירוג קושי.
- **מי צבר כמה נקודות** — שחקנים משתי הקבוצות עם הנקודות שלהם באותו מחזור, ממוינים מהגבוה לנמוך.
- פירוק קצר לכל שחקן בולט (שערים/בישולים/ספיגות/דקות) — אותו פורמט `statsData`.

### למה
- הקשר מהיר: רואים משחק בלוח ורוצים לדעת "מי הבקיע/בישל/ספג" בלי לחפש שחקן־שחקן.
- לזהות שחקנים חמים מקבוצה יריבה שהיו מעורבים במשחק טוב — קלט לחילוף/watchlist.
- לראות ביצועי השחקנים **שלי** באותו משחק במבט אחד.

### UX מוצע
- **טריגר:** כל שורת משחק / כרטיס משחק ניתן ללחיצה (cursor-pointer, aria). לחיצה פותחת `MatchDetailModal`.
- **מבנה המודאל:**
  - כותרת: `בית X:Y חוץ`, תאריך/שעה, לוגואים.
  - שתי עמודות (בית / חוץ) או טבלה אחת עם תג קבוצה — שורה לשחקן: `שם · עמדה · דקות · נק' · פירוק`.
  - **הדגשת שחקנים מהסגל שלי** (XI/ספסל) בצבע, ושורת סיכום "הסגל שלי במשחק הזה: N נק'".
  - למשחק עתידי (בלי תוצאה): להציג דירוג קושי + הרכבים/שחקנים צפויים אם יש, ולא טבלת נקודות.
  - סגירה `Esc` / רקע · RTL מלא.

### נתונים — כבר קיימים ב־DB
| טבלה | תפקיד |
|---|---|
| `fixtures` + `gameweeks` | פרטי המשחק: `homeTeamId`/`awayTeamId`, `kickoff`, `homeScore`/`awayScore`, מספר מחזור. |
| `player_round_stats` | נקודות + `statsData` לכל `(playerId, gameweekNumber)` — הבסיס ל"מי צבר כמה". מסננים לפי המחזור של המשחק ולפי שחקני שתי הקבוצות. |
| `player_snapshots` | שיוך שחקן→קבוצה **באותו מחזור** (`teamId` לכל `gameweek_number`) — לזהות מי שיחק לכל צד גם אם שחקן עבר קבוצה מאז. עדיף על `players.teamId` החי. |
| `my_squad` / `final_squads` | לסמן/לסכם את שחקני הסגל שלי במשחק. |

reuse: אותו `parseStatsDataRaw` / `STAT_LABELS` מ־`src/lib/stats.ts`.

### סקיצת מימוש
**החלטה שננעלה:** מציגים את **כל** שחקני שתי הקבוצות, אבל שחקני **הסגל שלי מוצמדים לראש הרשימה ומודגשים** (ואז השאר, ממוין מהגבוה לנמוך).

- **Server:** route `/(api)/match/[fixtureId]` — שולף את ה־`fixture` (מחזור + שתי קבוצות), ואז `player_round_stats` למחזור הזה מסונן לשחקני שתי הקבוצות. שיוך קבוצה דרך `player_snapshots` לאותו `gameweekNumber`.
- **טעינה עצלה:** כמו פיצ'ר 1 — לטעון רק בפתיחת המודאל, לא מראש.
- **UI:** קומפוננטה `MatchDetailModal.svelte`. שורות המשחק ב־`/squad` וה־`FixtureStrip` מקבלים `onSelect(fixtureId)`.
- **שיתוף עם פיצ'ר 1:** לחיצה על שם שחקן בתוך מודאל המשחק יכולה לפתוח את drill-down השחקן (פיצ'ר 1) — לתאם ניווט בין המודאלים.

### פתוחות / סיכונים
- מיפוי `sport5RoundId` → `gameweekNumber` nullable — משחק שלא ממופה למחזור לא יוכל להציג נקודות. fallback: להציג רק פרטי משחק בלי טבלת שחקנים.
- `FixtureStrip` מציג משחקים **עתידיים** (בלי תוצאה) — המודאל חייב לטפל יפה במצב "אין עדיין נתונים".
- ביצועים: לא לשלוף את כל `player_round_stats`; לסנן לפי מחזור + שתי הקבוצות בלבד.
